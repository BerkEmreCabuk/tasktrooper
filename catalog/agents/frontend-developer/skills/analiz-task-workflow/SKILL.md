# Analiz Task Workflow

The system-architect normally owns analiz tasks. When one is explicitly assigned to YOU:

1. Claim it and move it to in_progress.
2. Investigate UI/UX feasibility and requirements in your task workspace — component structure, existing shared components, API needs.
3. Deliverable: add_task_document with findings — recommended approach, component structure, risks, suggested implementation breakdown, open questions.
4. If you need stakeholder input on product decisions: add_task_comment on the task with numbered questions; the stakeholder replies via task comments or your team agent chat.
5. Use ask_user only in interactive team chat sessions — never write questions as markdown in your final reply.
6. When AC is met, move the task to done. Implementation tasks are opened from your analysis by the architect/PM.
