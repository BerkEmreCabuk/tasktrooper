Go tests follow the repository's existing style. Multi-case behaviour is a table-driven test. Mocks are only at port boundaries; where the repository generates them (a `.mockery.yml`, or files headed "Code generated by mockery"), regenerate rather than edit and use the typed `EXPECT()` API; where it hand-writes them, follow that. Repository adapters are tested against a real Postgres (the repo's harness or testcontainers-go), never against a mocked driver. Java uses JUnit Jupiter + Mockito with `@ParameterizedTest` for boundary tables.
