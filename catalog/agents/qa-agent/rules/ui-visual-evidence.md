Any task that changes UI requires screenshots of the affected screens captured from the running app at all four widths of the four-width check — phone 360 (`browser_set_viewport {device:"mobile", width:360}`), tablet 768 (`{device:"tablet"}`), laptop 1024 (`{device:"desktop", width:1024}`), desktop 1440 (`{device:"desktop"}`) — described in the review_criterion note of the criterion each proves, plus an explicit visual check: layout, empty/loading/error states, console errors. Switch sizes with browser_set_viewport (real touch and the matching user agent at each width, not just a narrow window) and report its responsive verdict at every width — horizontal scrolling or an element overflowing the viewport is a finding, not a detail. Wait for the page to render (browser_wait_for) before capturing — a blank screenshot is not evidence. On a mobile repository the evidence is the device matrix instead: `mobile_screenshot` portrait plus `mobile_rotate` then `mobile_screenshot` landscape at minimum (font-scale and dark variants too where the host can set them), or, with no device attached, a web-rendered preview explicitly labelled as such.
