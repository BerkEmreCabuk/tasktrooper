# TaskTrooper UI

The desktop app's user interface: a React 19 + TypeScript SPA built with Vite,
styled with Tailwind v4 and Radix primitives. The Electron shell in `..` (the desktop shell)
bundles this build and serves it from `app://tasktrooper`; it also runs in a
plain browser against a local server, which is how it is developed.

It is not a deployable web app. There is one user, one workspace, and one
server — the Go binary in `../server`, started by the desktop app on this
machine — and every call goes to it with a bearer token the shell states at
runtime.

## Development in a browser

```bash
npm ci
npm run dev      # http://localhost:3200
```

`npm run dev` starts Vite on port 3200 (strict) and proxies `/v1`, `/admin` and
`/health` to `http://localhost:8085`, so a locally running server works with
`VITE_API_BASE` left empty.

Copy `.env.example` to `.env.local` and set `VITE_API_KEY` to the server's
`SERVER_API_KEY`. Without it the app renders a configuration error instead of
mounting: there is no sign-in screen, so a build with no token could only ever
be refused by the server.

## Build and check

```bash
npx tsc --noEmit       # type check
npm run build          # tsc -b + vite build -> dist/
npm run check:locales  # en/tr key parity
npm run preview        # serve the built dist/
```

The desktop package builds this itself (`npm --prefix ui run build`) and
copies `dist/` into the app bundle.

## Environment variables

All `VITE_*` values are **compile-time**: Vite inlines them into the bundle, so
changing one requires a rebuild, not a restart.

| Variable | Purpose |
|---|---|
| `VITE_API_BASE` | Where API calls go. Empty means "same origin, no prefix" — what the dev proxy serves. Ignored inside the desktop shell, which states the base itself (`http://127.0.0.1:<port>`, no path suffix). |
| `VITE_API_KEY` | Bearer token for the local server; must match its `SERVER_API_KEY`. Ignored inside the desktop shell, which states its own token. |

## Auth

There is no account and no login. `src/lib/auth.ts` resolves one token:

1. `window.__tasktrooperDesktop.apiToken` — generated by the desktop app on
   first run, kept in the OS keychain, and handed to the server it spawns.
2. `VITE_API_KEY` — browser development.

`main.tsx` refuses to mount with neither, and `authHeaders()` in `src/api.ts` is
the only place the token is read into a request.

## Layout

| Path | What it holds |
|---|---|
| `src/pages/` | Route targets |
| `src/components/ui/` | Atoms (button, card, input, …) |
| `src/components/<feature>/` | Molecules and organisms per feature |
| `src/components/layout/` | Shells, sidebar, header, route gate |
| `src/api.ts` | Every call to the server, one function per endpoint |
| `src/lib/desktop-bridge.ts` | The typed contract with `../src/ipc/host.ts` |
| `src/locales/{en,tr}` | UI strings; `tr` must match `en` key for key |
